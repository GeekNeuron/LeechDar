# LeechDar

ربات شخصی تلگرامی برای دانلود از تورنت، لینک مستقیم، یوتیوب و صدها
سایت دیگه، Mega.nz، و هاست‌های پریمیوم (از طریق JDownloader) —
با آپلود خودکار به تلگرام، گوگل‌درایو، هر کلاود دیگه‌ای (rclone)،
GoFile یا PixelDrain. مدیریت کامل از داخل خود تلگرام، با یه داشبورد
وب اختیاری (هم به‌صورت Mini App داخل تلگرام، هم تو مرورگر معمولی).

فقط برای استفاده‌ی شخصی از محتوای بدون کپی‌رایت طراحی شده (لینوکس،
اوپن‌سورس، Creative Commons، Public Domain و مشابه).

## امکانات

**منابع دانلود**
- تورنت (مگنت‌لینک یا فایل `.torrent`) از طریق qBittorrent
- لینک مستقیم HTTP/HTTPS/FTP از طریق aria2 — با تشخیص خودکار نوع
  لینک حتی وقتی پسوند فایل مشخص نیست
- یوتیوب و صدها سایت دیگه از طریق yt-dlp، با دانلود خودکار زیرنویس
- Mega.nz
- فوروارد به JDownloader برای هاست‌های پریمیوم یا سایت‌های کپچادار
- RSS با قانون فیلتر، برای دانلود خودکار قسمت‌های تازه
- جستجوی تورنت از داخل تلگرام (با پلاگین‌های جستجوی خود qBittorrent)
- آپلود یه فایل معمولی (غیرتورنت) به‌عنوان تورنت جدید — خودش seed
  می‌کنه و مگنت‌لینک برمی‌گردونه تا بقیه هم بتونن ازت دانلود کنن

**مقصد آپلود (هم‌زمان به چندتا)**
- تلگرام (Bot API معمولی تا ۵۰ مگابایت، یا با حساب کاربری خودت تا
  ۲ گیگ/۴ گیگ با پریمیوم) — پارت‌های تقسیم‌شده به‌صورت آلبوم فرستاده
  می‌شن، نه تک‌تک
- گوگل‌درایو
- هر کلاود دیگه‌ای از طریق rclone
- GoFile و PixelDrain (بدون نیاز به اکانت)

**آماده‌سازی قبل از آپلود**
- زیپ‌کردن خودکار یا اجباری، با رمزنگاری AES اختیاری
- تقسیم به پارت‌های هم‌سایز دلخواه، خودکار بر اساس سقف مقصد، یا
  دقیقاً N پارت مساوی
- آنزیپ/استخراج آرشیو (zip, 7z, rar)
- انتخاب فایل خاص از یه تورنت چندفایلی قبل از دانلود
- تغییر نام، ادغام چند تورنت تو یه زیپ
- تبدیل فرمت، برش، واترمارک متنی، استخراج صدا، و گرفتن thumbnail
  با ffmpeg

**مدیریت و قابلیت‌اطمینان**
- پایداری کامل با SQLite — ری‌استارت ربات چیزی رو از دست نمی‌ده
- صف و محدودیت تعداد دانلود هم‌زمان، روی هر منبعی یکسان
- زمان‌بندی — دانلود جدید فقط تو یه بازه‌ی ساعتی مشخص شروع بشه
- جلوگیری از دانلود تکراری
- چک فضای آزاد دیسک قبل از هر دانلود
- تلاش مجدد خودکار و مدیریت محدودیت نرخ تلگرام روی آپلودها
- اعلان جایگزین با ntfy.sh وقتی خود تلگرام جواب نده
- بک‌آپ/ریستور تنظیمات و فیدهای RSS
- تایید دوم قبل از حذف قطعی یه دانلود
- کنترل نسبت/زمان سید تورنت‌ها
- چندکاربره — هر کاربر مجاز تنظیمات کاملاً جدای خودش رو داره
- لاگ فایل چرخشی، health-check استارتاپ، آپدیت خودکار از ریپو با یه دستور

## شروع سریع

تنها چیزی که واقعاً از قبل لازم داری یه **توکن ربات تلگرامه** — از
[@BotFather](https://t.me/BotFather) بگیر (`/newbot`).

```bash
git clone <لینک ریپوی خودت> leechdar
cd leechdar
cp .env.example .env
```

تو `.env`، فقط `TELEGRAM_BOT_TOKEN` رو پر کن. بقیه (آیدی تلگرام خودت،
اتصال qBittorrent) نیازی نیست از قبل بدونی — بعد از بالا اومدن ربات
از همون چت تنظیمشون می‌کنی:

- اولین نفری که به ربات پیام بده، خودکار **مالک** می‌شه (نیازی به
  دونستن آیدی عددی خودت از قبل نیست)
- بعدش `/setup` بزن تا اتصال qBittorrent رو از داخل همون چت تنظیم کنی

برای اجرا، سه راه داری — هر کدومی که راحت‌تره:

### روش ۱: Docker (پیشنهادی برای سرور)

```bash
docker compose up -d --build
```

qBittorrent و ربات با هم بالا میان. اولین بار برو
`http://<آی‌پی سرور>:8080`، پسورد یوزر وب qBittorrent رو تنظیم کن،
بعد همون اطلاعات رو با `/setup` تو تلگرام وارد کن (یا مستقیم
`QB_HOST=qbittorrent` و بقیه رو تو `.env` بذار، چون داکر خودش این
سرویس رو با همین اسم می‌شناسه).

### روش ۲: سرور لینوکسی بدون Docker (systemd)

```bash
sudo apt update && sudo apt install -y python3-venv qbittorrent-nox aria2 ffmpeg git
git clone <لینک ریپوی خودت> /opt/leechdar
cd /opt/leechdar
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # TELEGRAM_BOT_TOKEN رو پر کن

sudo cp leechdar.service /etc/systemd/system/
sudo nano /etc/systemd/system/leechdar.service   # User و مسیر رو با خودت هماهنگ کن
sudo systemctl daemon-reload
sudo systemctl enable --now leechdar
journalctl -u leechdar -f
```

### روش ۳: ویندوز/مک شخصی

```bash
# qBittorrent رو از qbittorrent.org نصب کن (Web UI رو فعال کن)
# aria2، ffmpeg اختیاری‌ان (brew install aria2 ffmpeg / از سایت رسمیشون رو ویندوز)

git clone <لینک ریپوی خودت> leechdar
cd leechdar
python -m venv venv
# ویندوز: venv\Scripts\activate
# مک: source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # TELEGRAM_BOT_TOKEN رو پر کن

python bot.py
```

هر سه روش، بعد از بالا اومدن، همون تجربه رو می‌دن: برو تو تلگرام،
`/start` بزن، `/setup` بزن، و شروع کن.

## دستورات

### شروع و راه‌اندازی

| دستور | کاربرد |
|---|---|
| `/start` | معرفی و راهنما |

### افزودن دانلود

فقط لینک (مگنت، HTTP/HTTPS، یوتیوب، Mega) یا فایل `.torrent` رو
بفرست — ربات خودش تشخیص می‌ده از کدوم منبع دانلودش کنه. فایل معمولی
(غیرتورنت) بفرستی، ازش تورنت می‌سازه و سیدش می‌کنه.

| دستور | کاربرد |
|---|---|
| `/ytdl <لینک>` — `/forceytdl <لینک>` | دانلود صریح با yt-dlp |
| `/leech <لینک>` — `/forceleech <لینک>` | دانلود صریح لینک مستقیم با aria2 |
| `/mega <لینک>` — `/forcemega <لینک>` | دانلود صریح از Mega.nz |
| `/jdadd <لینک>` | فوروارد لینک به JDownloader |
| `/forceadd <مگنت>` | افزودن تورنت حتی اگه قبلاً تکراری تشخیص داده شده |
| `/search <عبارت>` | جستجوی تورنت |
| `/searchadd <شماره>` | دانلود نتیجه‌ی شماره‌ی X از آخرین جستجو |

## تنظیمات

همه‌ی تنظیمات رو می‌شه یا مستقیم تو `config.py` (کپی‌شده از
`config.example.py`) ویرایش کرد، یا به‌عنوان environment variable
ست کرد (برای Docker/systemd راحت‌تره) — هر دو هم‌زمان کار می‌کنن و
مقدار env اولویت داره.

### پایه

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | توکن از BotFather (الزامی) |
| `ALLOWED_USER_IDS` | خالی | آیدی(های) مجاز، کاما جدا؛ خالی = اولین پیام‌دهنده خودکار مالک می‌شه |
| `QB_HOST` / `QB_PORT` / `QB_USERNAME` / `QB_PASSWORD` | `localhost` / `8080` / `admin` / `adminadmin` | اتصال qBittorrent (یا با `/setup` تنظیمش کن) |
| `POLL_INTERVAL_SECONDS` | `15` | هر چند ثانیه وضعیت دانلودها چک بشه |
| `AUTO_UPLOAD_ON_COMPLETE` | `true` | `false` یعنی صبر کن تا `/upload` دستی بزنی |
| `MAX_CONCURRENT_DOWNLOADS` | `2` | چندتا دانلود هم‌زمان؛ بقیه صف می‌شن |
| `MIN_FREE_DISK_GB` | `5` | زیر این مقدار، دانلود جدید رد می‌شه |
| `DISK_CHECK_PATH` | `.` | مسیری که فضای آزادش چک می‌شه |
| `STOP_DUPLICATES` | `true` | جلوگیری از دانلود تکراری |
| `LOG_LEVEL` / `LOG_FILE` | `INFO` / `work/logs/leechdar.log` | سطح و مسیر لاگ |
| `REQUIRE_CANCEL_CONFIRM` | `true` | تایید دوم قبل از `/cancel` قطعی |

### آپلود تلگرام با حجم بالا (حساب کاربری)

برای رد شدن از سقف ۵۰ مگابایتی Bot API:

1. برو https://my.telegram.org → API Development Tools → `api_id` و `api_hash` رو بردار
2. `python generate_session.py` رو بزن، شماره و کد تایید رو وارد کن
3. مقادیر چاپ‌شده رو بذار:

| متغیر | توضیح |
|---|---|
| `TELEGRAM_UPLOAD_MODE` | `bot_api` (۵۰MB) یا `pyrogram_user` (۲GB/۴GB) |
| `TELEGRAM_IS_PREMIUM` | `true` برای سقف ۴GB |
| `PYROGRAM_API_ID` / `PYROGRAM_API_HASH` / `PYROGRAM_SESSION_STRING` | از مرحله‌ی بالا |

یا در حین کار: `/uploadmode user` و `/premium on`.

### زیپ و اسپیلت

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `SPLIT_SIZE_MB` | خالی | سایز ثابت پارت؛ خالی = خودکار بر اساس سقف مقصد |
| `AUTO_ZIP_MULTI_FILE_TORRENTS` | `true` | تورنت چندفایلی خودکار زیپ بشه |
| `DELETE_AFTER_UPLOAD` | `false` | بعد از آپلود موفق از دیسک پاک بشه |
| `CREATED_TORRENTS_DIR` | `work/created_torrents` | محل فایل‌هایی که قراره تورنت بشن |

### گوگل‌درایو

1. https://console.cloud.google.com → پروژه بساز → فعال کن **Google Drive API**
2. `Credentials` → **OAuth client ID (Desktop app)** → فایل JSON رو
   `credentials.json` نام بذار (یا تو `gdrive-data/` برای Docker)
3. تنظیم کن:

| متغیر | توضیح |
|---|---|
| `GDRIVE_ENABLED` | `true` برای فعال‌سازی |
| `GDRIVE_CREDENTIALS_FILE` / `GDRIVE_TOKEN_FILE` | مسیر فایل‌های OAuth |
| `GDRIVE_FOLDER_ID` | خالی = روت درایو |

اولین آپلود یه لینک تایید مرورگر می‌ده (رو سرور بدون مرورگر، لینک
تو لاگ چاپ می‌شه؛ بازش کن رو کامپیوتر خودت و `gdrive_token.json` رو
دستی به سرور منتقل کن).

### rclone (هر کلاودی: Dropbox، S3، Mega، OneDrive، حتی خود گوگل‌درایو)

1. rclone رو نصب کن (تو Docker از قبل هست)
2. `rclone config` رو **رو کامپیوتر خودت** بزن (نیاز به لاگین تعاملی داره)
3. فایل `rclone.conf` ساخته‌شده رو کنار `bot.py` بذار (یا
   `rclone-config/rclone.conf` برای Docker)

| متغیر | توضیح |
|---|---|
| `RCLONE_ENABLED` | `true` برای فعال‌سازی |
| `RCLONE_REMOTE` | مثلاً `gdrive:LeechDar/` |
| `RCLONE_BINARY` | پیش‌فرض `rclone` |

### GoFile و PixelDrain

بدون اکانت هم کار می‌کنن:

| متغیر | توضیح |
|---|---|
| `GOFILE_ENABLED` / `GOFILE_API_TOKEN` | توکن اختیاری برای حساب‌دار بودن |
| `PIXELDRAIN_ENABLED` / `PIXELDRAIN_API_KEY` | کلید اختیاری |

### Mega.nz

| متغیر | توضیح |
|---|---|
| `MEGA_EMAIL` / `MEGA_PASSWORD` | خالی = ورود anonymous (برای لینک‌های عمومی کافیه) |

از کتابخونه‌ی غیررسمی `mega.py` استفاده می‌کنه. اگه با خطای مربوط به
`asyncio`/`tenacity` مواجه شدی: `pip install --upgrade tenacity`.

### JDownloader

لینک رو به JDownloader (که رو سیستم خودت بازه) فوروارد می‌کنه —
برای هاست‌های پریمیوم یا سایت‌های کپچادار که این ربات خودش نمی‌تونه
مستقیم ازشون دانلود کنه. دانلود واقعی رو خود JDownloader انجام می‌ده.

1. اکانت رایگان بساز: https://my.jdownloader.org
2. برنامه‌ی دسکتاپ JDownloader رو با همون اکانت وصل کن

| متغیر | توضیح |
|---|---|
| `JDOWNLOADER_ENABLED` | `true` برای فعال‌سازی |
| `JDOWNLOADER_EMAIL` / `JDOWNLOADER_PASSWORD` | همون اکانت MyJDownloader |
| `JDOWNLOADER_DEVICE_NAME` | اسم دستگاهی که تو JDownloader می‌بینی |

### aria2 (لینک مستقیم)

نیازی به سرویس جدا نیست؛ خود ربات دیمون `aria2c` رو بغل خودش بالا
میاره — فقط باینری‌ش باید نصب باشه (تو Docker از قبل هست).

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `ARIA2_HOST` / `ARIA2_PORT` | `http://localhost` / `6800` | آدرس RPC داخلی |
| `ARIA2_SECRET` | — | رمز داخلی؛ عوضش کن |
| `ARIA2_DOWNLOAD_DIR` | `work/aria2_downloads` | محل ذخیره |
| `ARIA2_BINARY` | `aria2c` | مسیر باینری |

### yt-dlp

| `YTDLP_SUBTITLES` | `false` | دانلود خودکار زیرنویس |
| `YTDLP_SUB_LANGS` | `fa,en` | زبان‌های زیرنویس، کاما جدا |

| `SEED_TIME_LIMIT_MIN` | `-2` | همون منطق، به دقیقه |

### زمان‌بندی دانلود

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `SCHEDULE_ENABLED` | `false` | فعال‌سازی بازه‌ی زمانی |
| `SCHEDULE_START_HOUR` / `SCHEDULE_END_HOUR` | `0` / `24` | بازه‌ی ۲۴ساعته (مثلاً `1` تا `7`)؛ بازه‌ی رد شده از نیمه‌شب هم درست کار می‌کنه |

دانلودی که از قبل شروع شده، با رسیدن به انتهای بازه قطع نمی‌شه —
فقط شروع دانلودهای جدید محدود می‌شه. بیرون از بازه، دانلود جدید صف
می‌مونه و با باز شدن بازه خودکار ادامه پیدا می‌کنه.

### داشبورد وب

```
WEBUI_ENABLED=true
WEBUI_PASSWORD=یه-رمز-قوی
```

بعد `http://<آی‌پی>:8090` رو با همون رمز باز کن — لیست دانلودها،
افزودن لینک جدید، انتخاب فایل، و تنظیمات از مرورگر.

برای باز کردنش **داخل خود تلگرام** (به‌جای مرورگر جدا) با `/webapp`:
دکمه‌ای میاد که چون initData امضاشده‌ی تلگرام رو می‌فرسته، خودکار با
همون هویت تلگرامی وارد می‌شه، بدون نیاز به تایپ رمز.

⚠️ تلگرام فقط لینک **HTTPS عمومی** رو به‌عنوان WebApp قبول می‌کنه، نه
`http://localhost`. برای `/webapp` باید سرورت دامنه + HTTPS داشته
باشه (مثلاً پشت [Caddy](https://caddyserver.com/) که خودش گواهی
Let's Encrypt می‌گیره، یا یه Cloudflare Tunnel/ngrok موقت برای تست):

```
WEBUI_PUBLIC_URL=https://leechdar.yourdomain.com
```

بدون این، بقیه‌ی ربات و خود داشبورد (تو مرورگر معمولی با رمز) عادی
کار می‌کنه؛ فقط دکمه‌ی `/webapp` غیرفعال می‌مونه.

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `WEBUI_ENABLED` | `false` | فعال‌سازی داشبورد |
| `WEBUI_HOST` | `127.0.0.1` | رو Docker معمولاً `0.0.0.0` |
| `WEBUI_PORT` | `8090` | پورت داشبورد |
| `WEBUI_PASSWORD` | — | رمز ورود از مرورگر معمولی |
| `WEBUI_PUBLIC_URL` | خالی | لینک HTTPS عمومی برای دکمه‌ی `/webapp` |

### اعلان جایگزین (ntfy)

وقتی آپلود به تلگرام (بعد از چندبار تلاش مجدد) بازم شکست بخوره:

```
NTFY_ENABLED=true
NTFY_URL=https://ntfy.sh/یه-اسم-تصادفی-و-خصوصی
```

اپ [ntfy](https://ntfy.sh/) رو رو گوشیت نصب و همون تاپیک رو subscribe کن.

## چندکاربره

هر آیدی تلگرام مجاز (که اولین‌بار خودکار claim کرده یا با `/adduser`
اضافه شده) تنظیمات کاملاً جدای خودش رو داره — مقصد آپلود، حالت
آپلود، سایز پارت، زیپ رمزدار، همه مستقل، چون تو دیتابیس per-user
ذخیره می‌شن. تشخیص «کاربر» بر اساس چت خصوصیه؛ تو یه گروه مشترک همه
یه `chat_id` یکسان می‌بینن، پس برای چت خصوصی با هرکس جدا طراحی شده،
نه گروه.

تنظیمات زیرساختی مثل اتصال qBittorrent، rclone، گوگل‌درایو و بقیه‌ی
سرویس‌ها سراسری‌ان (یه بار با `/setup` یا تو `config.py` تنظیم
می‌شن، مشترک بین همه‌ی کاربرهای مجاز).

## امنیت

چک دسترسی **سراسریه** — قبل از پردازش هر دستور یا پیامی، آیدی
فرستنده با لیست کاربران مجاز (ترکیب `ALLOWED_USER_IDS` تو کانفیگ +
جدول کاربران تو دیتابیس) چک می‌شه؛ دستورات مدیریتی (افزودن/حذف
کاربر، آپدیت از ریپو) علاوه‌براین فقط برای مالک بازن.

داشبورد وب با یه رمز ساده + کوکی session کار می‌کنه و محافظت CSRF
نداره — برای استفاده‌ی شخصی پشت شبکه‌ی قابل‌اعتماد یا reverse proxy
کافیه؛ رو اینترنت کاملاً باز بدون HTTPS جلوش قرارش نده.

## بازسازی فایل از روی پارت‌ها

بعد از دریافت همه‌ی پارت‌ها (`movie.mkv.zip.001`, `.002`, ...) از
تلگرام یا هر مقصد دیگه، همه رو تو یه پوشه بذار:

```bash
python join_parts.py "movie.mkv.zip" /path/to/folder
```

## آپلود روی گیت‌هاب

```bash
cd leechdar
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/<username>/<repo-name>.git
git push -u origin main
```

`.gitignore` طوری تنظیم شده که `config.py`، `.env`،
`credentials.json`، `gdrive_token.json`، `*.session`، و پوشه‌های
داده‌ای (`work/`, `qbittorrent-config/`, `gdrive-data/`,
`rclone-config/`) هرگز commit نمی‌شن. اگه ریپو رو پابلیک می‌کنی، قبل
از push یه بار `git status` بزن و مطمئن شو هیچ‌کدوم اینا لیست نشدن.

بعد از push، کسی که می‌خواد از ریپوی تو کلون کنه فقط کافیه
`git clone` بزنه، `TELEGRAM_BOT_TOKEN` خودش رو بذاره، و اجرا کنه —
بقیه رو همون‌طور که بالاتر گفته شد از تو تلگرام تنظیم می‌کنه. برای
آپدیت گرفتن از همون ریپو، `/update` کافیه.

## محدودیت‌ها

- Bot API معمولی تلگرام برای دانلود فایل از کاربر سقف ۲۰ مگابایت
  داره (جدا از سقف ۵۰ مگابایتی آپلود) — برای فایل‌های بزرگ‌تر
  (مثلاً «آپلود به‌عنوان تورنت» با فایل حجیم) باید حالت
  `pyrogram_user` فعال باشه.
- `/search` نیاز به نصب پلاگین جستجو از داخل خود qBittorrent داره
  (تب Search → Search plugins)؛ بدون پلاگین همیشه نتیجه‌ی خالی برمی‌گردونه.
- تورنت‌های دانلودشده با قانون RSS از صف/محدودیت هم‌زمانی مستقل
  عمل می‌کنن، چون خود qBittorrent مستقیم دانلودشون می‌کنه.
- کتابخونه‌ی Mega (`mega.py`) غیررسمیه و نگهداری فعالی نداره.
- داشبورد وب محافظت CSRF نداره (بخش امنیت رو ببین).
