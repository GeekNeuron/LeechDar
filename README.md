# LeechDar — ربات شخصی لیچ تورنت

فقط برای استفاده‌ی شخصی، برای دانلود محتوای بدون کپی‌رایت (لینوکس،
اوپن‌سورس، Creative Commons، Public Domain و مشابه).

قابل اجرا روی:
- **ویندوز/مک شخصی** (اجرای مستقیم پایتون)
- **سرور لینوکسی با Docker** (توصیه‌شده — یک دستور بالا میاد)
- **سرور لینوکسی بدون Docker** (با systemd)

## امکانات فعلی (همه‌ی فازها کامل شد ✅)

- گرفتن مگنت‌لینک یا فایل `.torrent` از تلگرام و دانلود با qBittorrent
- **تشخیص هوشمند هر لینکی** — پسوند مشخص نداشت؟ یه HEAD request واقعی
  می‌زنه و از Content-Type واقعی تشخیص میده فایل مستقیمه یا صفحه‌ی وب
- **آپلود به‌عنوان تورنت** — هر فایلی (غیر `.torrent`) بفرستی، خودش
  تبدیلش می‌کنه به یه تورنت واقعی، سیدش می‌کنه، و مگنت‌لینک برمی‌گردونه
  تا بقیه هم بتونن ازت دانلود کنن (بدون نیاز به tracker جدا)
- **دانلود لینک مستقیم (HTTP/HTTPS/FTP)** با aria2 (`/leech`)
- **دانلود از یوتیوب و صدها سایت دیگه با yt-dlp** (`/ytdl`)، با
  **دانلود خودکار زیرنویس** (`YTDLP_SUBTITLES`)
- **دانلود مستقیم از Mega.nz** (`/mega`) — تشخیص خودکار لینک
- **فوروارد لینک به JDownloader** (`/jdadd`) برای هاست‌های پریمیوم/کپچادار
- **RSS + دانلود خودکار** — فید + قانون فیلتر، خود qBittorrent
  تطابق‌ها رو دانلود می‌کنه و ربات خودکار آپلودشون می‌کنه
- **جستجوی تورنت از داخل تلگرام** (`/search`, `/searchadd`)
- **کنترل سید** (`/seedlimit`) + مقدار پیش‌فرض سراسری
- **داشبورد — هم تو خود تلگرام (Mini App/WebApp با `/webapp`)، هم تو
  مرورگر معمولی** — لیست دانلودها، افزودن لینک، انتخاب فایل، تنظیمات
- آپلود هم‌زمان به تلگرام، گوگل‌درایو، rclone، **GoFile، و/یا PixelDrain**
- **پارت‌های تلگرام به‌صورت آلبوم (media group)** فرستاده می‌شن، نه
  تک‌تک — تا ۱۰ پارت تو یه آلبوم واحد
- آپلود حجم بالا با حساب کاربری خودتون (Pyrogram)، سقف ۲GB یا ۴GB
- زیپ‌کردن خودکار/اجباری، **زیپ رمزدار با AES** (`/zippassword`)
- **اسپیلت با سایز دلخواه، خودکار بر اساس سقف مقصد، یا دقیقاً N پارت
  مساوی** (`/splitparts`)
- آنزیپ/استخراج آرشیو (`/extract`)، ترکیب چند تورنت (`/mergezip`)، رنیم
- **پایداری کامل با SQLite**
- **انتخاب فایل قبل/حین دانلود** (`/files`, `/selectfiles`)
- **صف و محدودیت هم‌زمانی** روی هر سه منبع دانلود
- **جلوگیری از دانلود تکراری** (با `/force*` دور بزن)
- **چک فضای آزاد دیسک** قبل از هر دانلود
- **تلاش مجدد خودکار + مدیریت FloodWait**
- **اعلان جایگزین با ntfy.sh** وقتی خود آپلود به تلگرام شکست بخوره
- **بک‌آپ/ریستور تنظیمات + فیدهای RSS** (`/backup`, `/restore`)
- **تایید دوم قبل از حذف قطعی** (`/cancel` → `/cancelconfirm`)
- **چندکاربره‌ی واقعی** — هر آیدی تلگرام مجاز، تنظیمات کاملاً جدای
  خودش رو داره (مقصد آپلود، حالت آپلود، سایز پارت، زیپ رمزدار، ...)
  چون تو دیتابیس per-user ذخیره می‌شه، نه مشترک
- **زمان‌بندی دانلود** — فقط تو یه بازه‌ی ساعتی مشخص (`SCHEDULE_START_HOUR`
  تا `SCHEDULE_END_HOUR`) دانلود جدید شروع می‌شه؛ بیرون از بازه صف
  می‌مونه و با باز شدن بازه خودکار ادامه پیدا می‌کنه
- **آپدیت خودکار از ریپو** (`/update`) — `git pull` می‌زنه و اگه چیزی
  عوض شده بود خودش ری‌استارت می‌کنه (فقط برای نصب‌های `git clone`)
- لاگ فایل چرخشی + `/log`، health-check استارتاپ
- مدیریت دانلود: `/status`, `/pause`, `/resume`, `/cancel`
- محدودیت دسترسی به آیدی تلگرام مشخص — **رو همه‌ی دستورات یکسان
  اعمال می‌شه** (یه چک سراسری قبل از هر چیزی، نه فقط بعضی دستورات)
- یک کدبیس، دو حالت تنظیم: مقدار مستقیم یا environment variable

## فیچرهایی که عمداً کنار گذاشته شدن

- **FFmpeg** (واترمارک، trim، تبدیل فرمت) — طبق نظر خودت حذف شد تا
  حجم پروژه بی‌خودی زیاد نشه

## چندکاربره — یه نکته‌ی مهم

تشخیص «کاربر» بر اساس آیدی چت خصوصیه (هر کسی تو `ALLOWED_USER_IDS`
جدا با ربات چت می‌کنه). یعنی اگه ربات رو تو یه **گروه مشترک** صدا
بزنی، همه‌ی اعضا یه `chat_id` مشترک می‌بینن و عملاً تنظیمات مشترک
می‌شه — این ربات برای **چت خصوصی با هرکس جدا** طراحی شده، نه گروه.

## زمان‌بندی دانلود

```
SCHEDULE_ENABLED=true
SCHEDULE_START_HOUR=1
SCHEDULE_END_HOUR=7
```

یعنی فقط بین ساعت ۱ بامداد تا ۷ صبح (به وقت سرور) دانلود جدید شروع
می‌شه. دانلودی که از قبل شروع شده، حتی اگه از بازه خارج بشیم،
نیمه‌کاره قطع نمی‌شه — فقط *شروع* دانلودهای جدید گیت می‌خوره.
بازه‌ای که از نیمه‌شب رد می‌شه (مثل `23` تا `7`) هم درست کار می‌کنه.

# روش ۱: اجرا روی سرور لینوکسی با Docker (توصیه‌شده)

نیاز به نصب جدای Python یا qBittorrent نداره — همه‌چیز تو کانتینر
میاد بالا.

1. Docker و Docker Compose رو نصب کن (اگه نداری):
   ```bash
   curl -fsSL https://get.docker.com | sh
   ```
2. ریپو رو بگیر:
   ```bash
   git clone <لینک ریپوی خودت> leechdar
   cd leechdar
   cp .env.example .env
   nano .env   # مقادیر رو پر کن (حداقل TELEGRAM_BOT_TOKEN, ALLOWED_USER_IDS, QB_PASSWORD)
   ```
3. بالا بیار:
   ```bash
   docker compose up -d --build
   ```
4. اولین بار برو `http://<آی‌پی سرور>:8080` و یوزر/پسوردی که تو `.env`
   گذاشتی رو تو qBittorrent هم تنظیم کن (`WebUI` تنظیماتش از پیش با
   env هماهنگ نیست، پس اولین بار دستی از تو پنل qBittorrent
   `Tools > Options > Web UI` پسورد رو با همون که تو `.env` گذاشتی ست کن).
5. لاگ‌ها:
   ```bash
   docker compose logs -f bot
   ```

برای آپلود حجم بالا (Pyrogram) یا گوگل‌درایو، همون مقادیر رو تو `.env`
پر کن (بخش‌های مربوطه پایین‌تر توضیح داده شده) و `docker compose up -d`
رو دوباره بزن.

# روش ۲: اجرا روی سرور لینوکسی بدون Docker (systemd)

```bash
sudo apt update && sudo apt install -y python3-venv qbittorrent-nox aria2
git clone <لینک ریپوی خودت> /opt/leechdar
cd /opt/leechdar
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
nano .env   # مقادیر رو پر کن؛ QB_HOST=localhost بمونه
```

`qbittorrent-nox` رو یه بار جدا اجرا کن و از `--webui-port` مطمئن شو
که با `QB_PORT` تو `.env` یکیه، بعد به‌عنوان سرویس systemd جدا هم
تنظیمش کن (خارج از اسکوپ این پروژه — مستندات خودِ qbittorrent-nox رو ببین).

بعد سرویس ربات رو نصب کن:
```bash
sudo cp leechdar.service /etc/systemd/system/
sudo nano /etc/systemd/system/leechdar.service   # User و مسیر رو با خودت هماهنگ کن
sudo systemctl daemon-reload
sudo systemctl enable --now leechdar
journalctl -u leechdar -f
```

# روش ۳: اجرا روی ویندوز/مک شخصی

1. **qBittorrent**: https://www.qbittorrent.org/download — نصب کن،
   `Tools > Options > Web UI` رو فعال کن (پورت/یوزر/پسورد تنظیم کن)
2. **Python 3.10+**: https://www.python.org/downloads/
3. **aria2** (اختیاری، فقط برای لینک مستقیم): مک `brew install aria2`،
   ویندوز از https://aria2.github.io/ (بدونش هم بقیه‌ی ربات عادی کار می‌کنه)
4. نصب کد:
   ```bash
   git clone <لینک ریپوی خودت> leechdar
   cd leechdar
   python -m venv venv
   # ویندوز: venv\Scripts\activate
   # مک: source venv/bin/activate
   pip install -r requirements.txt
   cp config.example.py config.py
   ```
5. `config.py` رو باز کن و `TELEGRAM_BOT_TOKEN`, `ALLOWED_USER_IDS`,
   `QB_USERNAME`, `QB_PASSWORD` رو بذار
6. اجرا:
   ```bash
   python bot.py
   ```

## آپلود حجم بالا با حساب کاربری (۲GB / ۴GB) — هر سه روش اجرا

Bot API تلگرام محدود به ۵۰ مگابایته. برای رد شدن از این سقف:

1. برو https://my.telegram.org، `API Development Tools`، یه اپ بساز،
   `api_id` و `api_hash` رو بردار
2. رو همون محیطی که ربات توش اجرا می‌شه (لوکال، یا داخل کانتینر با
   `docker compose run bot python generate_session.py`) بزن:
   ```bash
   python generate_session.py
   ```
3. مقادیر چاپ‌شده رو تو `config.py` یا `.env` بذار:
   ```
   TELEGRAM_UPLOAD_MODE=pyrogram_user
   TELEGRAM_IS_PREMIUM=false   # اگه پریمیوم داری true کن
   PYROGRAM_API_ID=...
   PYROGRAM_API_HASH=...
   PYROGRAM_SESSION_STRING=...
   ```

یا در حین اجرای ربات: `/uploadmode user` و `/premium on|off`.

## آپلود به گوگل‌درایو — هر سه روش اجرا

1. https://console.cloud.google.com → پروژه بساز → فعال کن
   **Google Drive API** → `Credentials` → **OAuth client ID (Desktop app)**
2. فایل JSON رو `credentials.json` نام بذار:
   - اجرای محلی: کنار `bot.py`
   - Docker: تو پوشه‌ی `gdrive-data/credentials.json` (مونت‌شده تو compose)
3. `GDRIVE_ENABLED=true` رو تو `config.py`/`.env` بذار
4. اولین آپلود درایو یه صفحه‌ی مرورگر برای اجازه باز می‌کنه (رو سرور
   بدون مرورگر، لینک تو لاگ چاپ می‌شه؛ بازش کن رو کامپیوتر خودت،
   اجازه بده، بعد `gdrive_token.json` رو دستی به سرور منتقل کن)

با `/destination gdrive` یا `/destination telegram,gdrive` مقصد آپلود رو عوض کن.

## آپلود با rclone (هر کلاودی: Dropbox، S3، Mega، OneDrive، و حتی خود گوگل‌درایو)

1. rclone رو نصب کن: https://rclone.org/downloads/ (تو Docker از قبل نصبه)
2. remote موردنظرت رو تنظیم کن (نیاز به لاگین تعاملی داره، پس اول‌بار
   رو خود کامپیوترت اجرا کن، نه سرور بدون مرورگر):
   ```bash
   rclone config
   ```
   اسم remote رو یادت بمونه (مثلاً `gdrive` یا `dropbox`)
3. فایل `rclone.conf` ساخته‌شده رو:
   - اجرای محلی: کنار همون مسیر پیش‌فرض rclone بذار (خودش پیدا می‌کنه)
   - Docker: تو پوشه‌ی `rclone-config/rclone.conf` بذار (مونت‌شده تو compose)
4. تو `config.py`/`.env`:
   ```
   RCLONE_ENABLED=true
   RCLONE_REMOTE=gdrive:LeechDar/
   ```
5. `/destination rclone` یا `/destination telegram,rclone` بزن

## دانلود با yt-dlp (یوتیوب و صدها سایت دیگه)

هیچ تنظیم اضافه‌ای لازم نداره — فقط لینک رو بفرست (یا `/ytdl <لینک>`).
کیفیت پیش‌فرض بهترین ویدیو+صدای موجوده؛ با `YTDLP_FORMAT` تو
`config.py` قابل تغییره (فرمت‌بندی طبق مستندات خود yt-dlp).

## دانلود لینک مستقیم با aria2

هیچ سرویس/کانتینر جدایی لازم نیست — خود ربات یه دیمون `aria2c` رو
بغل خودش بالا میاره؛ فقط باینری‌ش باید نصب باشه:

- **Docker**: از قبل تو ایمیج هست، کاری لازم نیست
- **ویندوز/مک/لینوکس محلی**: نصبش کن
  - اوبونتو/دبین: `sudo apt install aria2`
  - مک: `brew install aria2`
  - ویندوز: https://aria2.github.io/ (باینری رو تو PATH بذار)

فقط لینک مستقیم بفرست (یا `/leech <لینک>`) — ربات از روی پسوند فایل
(zip, iso, mp4, pdf, ...) خودش تشخیص میده که این aria2 هست نه yt-dlp.
اگه تشخیص اشتباه بود، صریح بگو: `/leech` یا `/ytdl`.

## دانلود از Mega.nz

فقط لینک مگا رو بفرست (یا `/mega <لینک>`)، خودش تشخیص میده. برای
فایل‌های داخل حساب شخصی (نه لینک عمومی)، `MEGA_EMAIL`/`MEGA_PASSWORD`
رو تو `config.py` بذار؛ وگرنه به‌صورت anonymous (برای لینک‌های عمومی
کافیه) کار می‌کنه.

⚠️ از کتابخونه‌ی غیررسمی `mega.py` استفاده می‌کنه (مگا خودش API رسمی
عمومی نداره). اگه یهو خطا داد، اول `pip install -U mega.py` رو امتحان
کن — ممکنه مگا یه چیزی رو تغییر داده باشه.

## فوروارد به JDownloader (هاست‌های پریمیوم / کپچادار)

برای سایت‌هایی که این ربات (نه خودش، نه yt-dlp، نه aria2) نمی‌تونه
مستقیم ازشون دانلود کنه — مثل هاست‌های پریمیوم یا سایت‌هایی با کپچا —
می‌شه لینک رو به JDownloader فوروارد کرد تا خودش (رو همون
کامپیوتری که JDownloader روشه) دانلودش کنه:

1. یه اکانت رایگان تو https://my.jdownloader.org بساز
2. خود برنامه‌ی JDownloader (دسکتاپ) رو با همون اکانت وصل کن
3. تو `config.py`:
   ```
   JDOWNLOADER_ENABLED=true
   JDOWNLOADER_EMAIL=...
   JDOWNLOADER_PASSWORD=...
   JDOWNLOADER_DEVICE_NAME=اسم دستگاهی که تو JDownloader می‌بینی
   ```
4. `/jdadd <لینک>` — لینک به صف JDownloader اضافه می‌شه و **اونجا**
   دانلود می‌شه، نه رو سرور این ربات.

## آپلود به GoFile و PixelDrain

هر دو بدون نیاز به اکانت کار می‌کنن (لینک عمومی/موقت)، یا با یه
توکن/کلید اختیاری که فایل‌ها تو حساب خودت بمونن:

```
GOFILE_ENABLED=true
GOFILE_API_TOKEN=   (اختیاری)

PIXELDRAIN_ENABLED=true
PIXELDRAIN_API_KEY=   (اختیاری)
```

بعد `/destination gofile` یا `/destination telegram,gofile,pixeldrain`.

## RSS و دانلود خودکار

فید رو اضافه کن، بعد یه قانون بساز که هر آیتم تازه‌ی مطابق رو خودکار
دانلود کنه:

```
/rssadd https://example.com/feed.xml my-feed
/rssrule my-rule 1080p my-feed
```

از این به بعد، هر بار که آیتم جدیدی تو فید بیاد که شامل کلمه‌ی
«1080p» باشه، خودِ qBittorrent دانلودش می‌کنه و ربات خودش تشخیص
می‌ده و طبق تنظیمات فعلی (`/destination`, `/tozip`, ...) آپلودش
می‌کنه. نتیجه به `RSS_NOTIFY_CHAT_ID` (پیش‌فرض: اولین آیدی تو
`ALLOWED_USER_IDS`) فرستاده می‌شه.

⚠️ تورنت‌های RSS از صف/محدودیت هم‌زمانی (`MAX_CONCURRENT_DOWNLOADS`)
مستقل عمل می‌کنن — چون خود qBittorrent مستقیم دانلودشون می‌کنه، نه
از مسیر تلگرام.

## جستجوی تورنت

```
/search ubuntu
```

نیاز به **نصب پلاگین جستجو** از داخل خود qBittorrent داره (تب
Search → Search plugins → نصب پلاگین‌های پیش‌فرض یا دلخواه). بدون
پلاگین، `/search` همیشه «نتیجه‌ای پیدا نشد» برمی‌گردونه — این
محدودیت خود qBittorrent‌ه، نه ربات.

## کنترل سید

پیش‌فرض سراسری با `SEED_RATIO_LIMIT` و `SEED_TIME_LIMIT_MIN` تو
`config.py` تنظیم می‌شه (`-2` = مقدار سراسری qBittorrent، `-1` =
بدون محدودیت، عدد مثبت = مقدار مشخص) و روی هر تورنت جدید خودکار
اعمال می‌شه. برای یه تورنت خاص جدا:
```
/seedlimit ab12cd34 1.5 120
```
(نسبت ۱.۵، حداکثر ۱۲۰ دقیقه سید)

## داشبورد وب

اگه ترجیح می‌دی از مرورگر مدیریت کنی، نه فقط تلگرام:

```
WEBUI_ENABLED=true
WEBUI_PASSWORD=یه-رمز-قوی-بذار
```

بعد سراغ `http://<آی‌پی سرور یا localhost>:8090` برو، رمز رو وارد
کن. از اونجا می‌تونی:
- لینک جدید (مگنت/مستقیم/یوتیوب) اضافه کنی
- لیست دانلودهای در جریان رو با وضعیت و درصد پیشرفت ببینی
- فایل‌های یه تورنت چندفایلی رو انتخاب/غیرفعال کنی
- یه دانلود رو لغو یا فوری آپلود کنی
- تنظیمات (مقصد آپلود، حالت آپلود، سایز پارت، زیپ اجباری) رو عوض کنی

⚠️ پیش‌فرض `WEBUI_HOST=127.0.0.1` یعنی فقط از خود سرور در دسترسه.
اگه می‌خوای از بیرون هم بهش وصل بشی، `WEBUI_HOST=0.0.0.0` بذار (تو
Docker از قبل همینه) — ولی چون احراز هویتش ساده‌ست (فقط یه رمز، بدون
HTTPS داخلی)، پشت یه reverse proxy با HTTPS (مثل Caddy/Nginx) قرارش
بده اگه رو اینترنت عمومی در دسترسه.

## داشبورد داخل خود تلگرام (Telegram Mini App)

به‌جای باز کردن یه تب مرورگر جدا، می‌تونی همون داشبورد رو **داخل خود
اپ تلگرام** باز کنی (دقیقاً مثل مینی‌اپ‌هایی که تو کانال‌ها می‌بینی) —
با `/webapp` یه دکمه می‌فرسته که با لمسش داشبورد همونجا باز می‌شه، و
چون initData امضاشده‌ی خود تلگرام رو می‌فرسته، **دیگه نیازی به تایپ
رمز نیست** — خودش می‌فهمه همون کاربر مجازی که ربات رو باز کرده.

⚠️ **محدودیت مهم (از طرف خود تلگرام، نه ما):** دکمه‌ی WebApp فقط با
لینک **HTTPS عمومی** کار می‌کنه — `http://localhost` یا IP بدون SSL
قبول نمی‌شه. یعنی برای استفاده از `/webapp` باید:

1. سرورت یه دامنه داشته باشه (یا حتی یه ساب‌دامین رایگان)
2. پشتش یه reverse proxy با HTTPS بذاری — ساده‌ترینش
   [Caddy](https://caddyserver.com/) هست (خودش گواهی SSL رایگان
   Let's Encrypt می‌گیره، فقط با یه خط تنظیمات):
   ```
   leechdar.yourdomain.com {
       reverse_proxy localhost:8090
   }
   ```
   یا برای تست سریع بدون دامنه‌ی خودت، یه Cloudflare Tunnel یا ngrok
   موقت بزن و لینک HTTPS که بهت میده رو تو `WEBUI_PUBLIC_URL` بذار.
3. `WEBUI_PUBLIC_URL=https://leechdar.yourdomain.com` رو تو
   `config.py`/`.env` بذار

بدون این، بقیه‌ی ربات (و حتی خود داشبورد تو مرورگر معمولی با رمز)
عادی کار می‌کنه — فقط دکمه‌ی `/webapp` کار نمی‌کنه.

## آپلود به‌عنوان تورنت (seed کردن فایل خودت)

هر فایلی که بفرستی و اسمش به `.torrent` ختم نشه، ربات فرض می‌کنه
می‌خوای ازش یه تورنت بسازی:

1. فایل رو از تلگرام می‌گیره
2. باهاش یه فایل `.torrent` واقعی می‌سازه (کتابخونه‌ی `torf`)
3. به qBittorrent می‌ده با `skip_checking` (چون خودمون مطمئنیم فایل
   کامله) — فوراً می‌شه ۱۰۰٪ و شروع به سید می‌کنه
4. مگنت‌لینک و خود فایل `.torrent` رو برات می‌فرسته

⚠️ **محدودیت از طرف خود تلگرام:** Bot API معمولی فقط اجازه‌ی دانلود
فایل‌های **تا ۲۰ مگابایت** رو می‌ده (حتی با اینکه سقف آپلودش ۵۰MB‌ه).
برای فایل‌های بزرگ‌تر باید حالت `pyrogram_user` فعال باشه.

## اعلان جایگزین با ntfy

وقتی آپلود به تلگرام (بعد از چندبار تلاش مجدد) بازم شکست بخوره، اگه
ntfy فعال باشه، یه اعلان یدکی هم از اون مسیر می‌فرسته — برای وقتی
خود تلگرام مشکل داره و نمی‌خوای بی‌خبر بمونی:

```
NTFY_ENABLED=true
NTFY_URL=https://ntfy.sh/یه-اسم-تصادفی-و-خصوصی-برای-خودت
```

بعد اپ [ntfy](https://ntfy.sh/) رو رو گوشیت نصب کن و همون تاپیک رو
subscribe کن.

| `/destination telegram\|gdrive\|rclone` | مقصد آپلود (چندتایی با کاما: `telegram,gdrive`) |
| `/uploadmode bot\|user` | حالت آپلود تلگرام |
| `/premium on\|off` | سقف ۲GB یا ۴GB برای حالت user |

| `/rename <hash8> <نام>` | تغییر نام قبل از آپلود |
| `/mergezip <hash8> <hash8> ...` | ادغام چند تورنت در یه زیپ |

| `/ytdl <لینک>` | دانلود صریح با yt-dlp (یا فقط لینک رو بفرست) |
| `/forceytdl <لینک>` | دانلود لینک حتی اگه تکراری تشخیص داده شده |
| `/leech <لینک مستقیم>` | دانلود صریح با aria2 (یا فقط لینک با پسوند فایل رو بفرست) |

| `/seedlimit <hash8> <نسبت> <دقیقه>` | محدودیت سید برای یه تورنت خاص |
| `/rssadd <لینک فید> [اسم]` | اضافه‌کردن فید RSS |
| `/rsslist` | لیست فیدهای اضافه‌شده |
| `/rssremove <اسم فید>` | حذف فید |
| `/rssrule <اسم> <کلمه‌کلیدی> [فید]` | قانون دانلود خودکار روی فید(ها) |
| `/rssrules` | لیست قوانین |
| `/rssruledel <اسم>` | حذف قانون |
| `/search <عبارت>` | جستجوی تورنت (نیاز به پلاگین جستجو تو qBittorrent) |
| `/searchadd <شماره>` | دانلود نتیجه‌ی شماره‌ی X از آخرین جستجو |
| `/webapp` | باز کردن داشبورد از داخل خود تلگرام (Mini App) |
| `/zippassword <رمز>` یا `off` | زیپ رمزدار (AES) برای آپلودهای بعدی |
| `/splitparts <N>` یا `auto` | اسپیلت به دقیقاً N پارت مساوی (به‌جای سایز ثابت) |
| `/cancelconfirm <hash8>` | تایید نهایی `/cancel` (حذف قطعی و برگشت‌ناپذیر) |
| `/backup` | گرفتن فایل بک‌آپ از تنظیمات + فیدهای RSS |
| `/restore` | بازگردوندن بک‌آپ (با ریپلای رو فایل JSON) |
| `/log` | آخرین خط‌های لاگ ربات |
| `/mega <لینک>` — `/forcemega <لینک>` | دانلود صریح از Mega.nz |
| `/jdadd <لینک>` | فوروارد لینک به JDownloader |
| `/update` | `git pull` + ری‌استارت خودکار (فقط نصب‌های git clone) |

برای **هر فایلی غیر از `.torrent`** که بفرستی، ربات دیگه نادیده‌ش
نمی‌گیره — خودکار تبدیلش می‌کنه به تورنت، سیدش می‌کنه، و مگنت‌لینک
برمی‌گردونه («آپلود به‌عنوان تورنت»).

`hash8` یعنی ۸ کاراکتر اول هش تورنت که با `/status` می‌بینید.

## یه رفع باگ امنیتی مهم

تا قبل از این نسخه، فقط چندتا از دستورات (`/status` و موارد مشابه)
واقعاً چک می‌کردن که فرستنده تو `ALLOWED_USER_IDS` هست یا نه؛ بقیه‌ی
دستورات (`/pause`, `/destination`, `/rssadd`, `/backup`, و ده‌ها
دستور دیگه) این چک رو نداشتن — یعنی هرکسی که یوزرنیم ربات رو پیدا
می‌کرد، نظری به محدودیت دسترسی، می‌تونست ازشون استفاده کنه. الان یه
چک دسترسی **سراسری** قبل از هر دستور یا پیامی اجرا می‌شه (با
`group=-1` تو python-telegram-bot)، پس این مشکل برای همه‌ی
دستورات (قبلی و بعدی) یکجا حل شد. با یه کاربر مجاز و یه کاربر
غیرمجاز فیک تست شد.

## محدودیت‌ها

- الگوریتم اعتبارسنجی initData تلگرام (امضای HMAC) رو کامل و واقعی
  تست کردم (initData معتبر، دستکاری‌شده، با توکن غلط، و منقضی‌شده —
  هر چهارتا درست رفتار کردن). چیزی که نتونستم تست کنم خود رندر واقعی
  صفحه داخل اپ تلگرام (نیاز به دامنه‌ی HTTPS عمومی + یه بات توکن واقعی
  + خود اپ تلگرام داره که این محیط نداره) — ولی چون منطق سمت سرور
  دقیقاً طبق مستندات رسمی تلگرامه، باید همونطوری کار کنه.
- «آپلود به‌عنوان تورنت» رو سر تا سر با یه qBittorrent واقعی تست کردم:
  فایل واقعی → تورنت واقعی → qBittorrent واقعاً تشخیص داد ۱۰۰٪ کامله
  و بدون دانلود دوباره سید کرد.
- تشخیص هوشمند لینک (content-sniffing) رو با درخواست HTTP واقعی به
  آدرس‌های واقعی گیت‌هاب تست کردم (هم حالت فایل مستقیم، هم صفحه‌ی وب).
- بک‌آپ/ریستور، تایید حذف، زیپ رمزدار (AES)، و اسپیلت N‌تایی همه با
  سناریوی واقعی (از جمله یه qBittorrent واقعی برای RSS) تست شدن.
- **GoFile و PixelDrain**: چرخه‌ی درخواست/پاسخ (از جمله مرحله‌ی
  دومرحله‌ایِ GoFile) با یه سرور HTTP محلی فیک تست شد که دقیقاً
  ساختار پاسخ واقعیشون رو برمی‌گردوند؛ اتصال واقعی به خود
  api.gofile.io/pixeldrain.com تو این محیط ممکن نبود.
- **Mega.nz و JDownloader**: فقط ساختار و منطق کد (و برای Mega، چرخه‌ی
  کامل صف/دانلود با یه دانلودر فیک) تست شد؛ اتصال واقعی به
  mega.nz یا api.jdownloader.org تو این محیط در دسترس نبود.
- **آلبوم تلگرامی**: منطق گروه‌بندی (حداکثر ۱۰ پارت در هر آلبوم،
  fallback به ارسال تکی وقتی پارتی از سقف بزرگ‌تره یا آلبوم شکست
  بخوره) با mock کامل `send_media_group` تست شد، همراه با یه سناریوی
  کامل `do_upload` که هم‌زمان تلگرام (آلبومی) و rclone (تکی) می‌فرسته.
- **آپدیت خودکار**: با یه ریپوی git واقعی (remote + دو clone جدا)
  تست شد — تغییر واقعی رو pull کرد، فایل واقعاً عوض شد، و حالت
  «از قبل آخرین نسخه» هم درست تشخیص داده شد.

- داشبورد وب رو با درخواست‌های HTTP واقعی (نه فیک) روی خود اپ
  FastAPI تست کردم — لاگین، داشبورد، تنظیمات، انتخاب فایل، افزودن و
  لغو، همه واقعاً از طریق HTTP چک شدن. چیزی که تست نشد اجرای واقعی
  Uvicorn روی یه پورت باز و باز کردنش تو مرورگر واقعی (چون این
  محیط GUI/مرورگر نداره)، ولی چون FastAPI مستقیم روی همون کد تست
  می‌شه، رفتارش باید یکی باشه.
- داشبورد وب محافظت CSRF نداره (فقط رمز + کوکی session). برای
  استفاده‌ی شخصی پشت یه شبکه‌ی قابل‌اعتماد یا reverse proxy کافیه؛
  رو اینترنت کاملاً باز قرارش نده.

- منطق RSS، کنترل سید، و ساختار API جستجو رو با یه نمونه‌ی واقعی
  qBittorrent (نصب و اجرا شده تو محیط توسعه‌ی خودم) تست کردم — فید
  واقعی گیت‌هاب اضافه شد، قانون واقعی ساخته شد، seed limit واقعی
  اعمال شد. تنها چیزی که نتونستم تست کنم نتیجه‌ی واقعی `/search`ه،
  چون نصب پلاگین جستجو از سرور پلاگین‌های qBittorrent نیاز داره که
  تو شبکه‌ی محدودشده‌ی من در دسترس نبود؛ ساختار فراخوانی API درسته
  و طبق مستندات رسمیه، فقط با پلاگین واقعی روی سیستم خودت باید
  نتیجه بده.
- منطق صف/پایداری/آپلود همه با تست‌های شبیه‌سازی‌شده (mock) بررسی
  شدن. نصب واقعی rclone در Dockerfile (که از rclone.org دانلود
  می‌کنه) رو نمی‌تونم تو محیط توسعه‌ی خودم بیلد و تست کنم (دسترسی
  شبکه محدوده)؛ وقتی خودت `docker compose up --build` زدی، اگه به
  مشکلی خوردی بگو تا رفع کنم.

- ربات فقط وقتی در حال اجراست کار می‌کنه (لوکال: تا وقتی ترمینال بازه؛
  Docker/systemd: به‌صورت خودکار روشن می‌مونه و با ری‌استارت سرور هم
  بالا میاد)
- `ALLOWED_USER_IDS` رو خالی نذار وگرنه هرکسی که یوزرنیم ربات رو پیدا
  کنه می‌تونه ازش استفاده کنه
- وضعیت صف (`pending`) هنوز تو حافظه‌ست؛ اگه ربات وسط پردازش ری‌استارت
  بشه، اون کار خاص از صف حذف می‌شه (فایل‌های خود qBittorrent دست
  نمی‌خورن، فقط باید دوباره `/upload` بزنی — اگه لازم شد این مورد رو
  هم به دیتابیس منتقل می‌کنم)
